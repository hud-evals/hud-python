Graders turn an agent's answer into a reward. HUD ships reusable ones so you don't hand-build common scoring logic. Yield the result (a `float` or a `Grade`) as the task's second yield.

```python
from hud import Grade
from hud.graders import BashGrader, Grader, LLMJudgeGrader, SubScore, combine
```

## What grading scores

Grading decides *what* the reward measures. Two framings cover most tasks:

- **Grade the answer** - compute a float from what the agent said.
- **Grade the world** - score the state the agent left behind: tests passing, a file written, a
  service responding. Because the agent acts on a real system through its
  [capabilities](/v6/reference/capabilities), this is **outcome verification**: the rigor of a test
  suite with no fixed protocol the agent has to follow.

## Approaches

Three approaches cover grading, in increasing power. Each produces the `float` or
[`Grade`](/v6/reference/types#grade) yielded as the task's second yield.

| Approach | When to reach for it | Example |
|----------|----------------------|---------|
| **Plain Python** | A reward you compute from the answer | `yield 1.0 if answer.strip() == "3" else 0.0` |
| **Async grader** | Score a command's exit code or an LLM's judgment of the answer | `yield (await BashGrader.grade(weight=1.0, command="pytest -q")).value` |
| **Composed** | Weight several graders into one reward, each subscore kept in the trace | `yield await combine(BashGrader.grade(...), LLMJudgeGrader.grade(...))` |

## Plain Python

Compare the answer in the task itself, with the rule that fits what the task asks for. A free-form
answer is better scored by `LLMJudgeGrader`, and a structured one by `@env.template(returns=...)`.

```python
@env.template()
async def capital(country: str = "France"):
    answer = yield f"What is the capital of {country}? Reply with the city name only."
    yield 1.0 if answer.strip().lower() == "paris" else 0.0
```

## `BashGrader`

Runs a shell command via `/bin/bash -lc` and scores by exit code (`1.0` if it exits `0`). Async; returns a `SubScore`. Needs `/bin/bash`: macOS, Linux, WSL, or a built image.

```python
@env.template()
async def fix_tests():
    answer = yield "Make the tests pass."
    result = await BashGrader.grade(weight=1.0, command="pytest -q", cwd="/workspace")
    yield result.value
```

`cwd` is the host directory to run in - for a workspace-backed task, pass the workspace root so the grader sees the same files the agent edited.

| Parameter | Default | Description |
|-----------|---------|-------------|
| `weight` | - | Weight in a composed grade. |
| `command` | - | Shell command to run. |
| `cwd` | `None` | Working directory. |
| `timeout_seconds` | `600` | Kill + score `0.0` on timeout. |

## `LLMJudgeGrader`

Scores an answer against weighted criteria with an LLM judge (uses the HUD gateway). Each criterion is graded `MET`/`UNMET` in parallel and combined by weight; no extra install needed.

```python
result = await LLMJudgeGrader.grade(
    weight=1.0,
    answer=answer,
    criteria=["Correct", ("Well-reasoned", 2.0)],
    question=prompt,
    model="claude-sonnet-5-5",
)
```

The default model is `claude-sonnet-5-5`. Pass `model` to use a different judge.

`criteria` items are strings, or `(requirement, weight)` tuples with a weight of 0 or more. An
empty rubric is a grading error.

The returned `SubScore` has one child per criterion: `name` is the requirement, `value` is
`1.0`/`0.0` for the verdict, and `info["reason"]` is the judge's justification. The rubric value
is the weighted mean of the verdicts: `sum(value * weight)` over the total weight. A judge reply
without a `MET` or `UNMET` verdict is a grading error.

## `combine` - compose multiple graders

`await combine(*items)` takes `SubScore`s and grader coroutines, runs the coroutines in parallel, and combines the results into a `Grade` whose reward is the weighted sum of the subscores. Positive weights sum to `1.0`. Negative weights are penalties, and nothing clamps, so a penalty can take the reward below 0. Repeated names get numeric suffixes (`BashGrader-1`, `BashGrader-2`).

```python
@env.template()
async def composed(answer: str = ""):
    answer = yield "Solve the task."
    yield await combine(
        BashGrader.grade(weight=0.5, command="pytest -q"),
        LLMJudgeGrader.grade(weight=0.3, answer=answer, criteria=["Matches the spec"]),
        SubScore(name="format", value=1.0 if answer.strip() == "42" else 0.0, weight=0.2),
    )
```

Each subscore appears in the trace, so a partial reward is legible. A `SubScore` can keep the subscores it was derived from on `children`, so a grading tree survives into the trace. How a node derives its value from its children is yours to write; for example, "tests pass via `pytest` or via `make test`" as one subscore:

```python
pytest_run = await BashGrader.grade(weight=1.0, command="pytest -q")
make_run = await BashGrader.grade(weight=1.0, command="make test")
tests = SubScore(
    name="tests",
    value=max(pytest_run.value, make_run.value),
    weight=0.5,
    children=[pytest_run, make_run],
)
```

## Custom graders

Subclass `Grader` and implement async `compute_score`, returning a `SubScore`:

```python
class LengthGrader(Grader):
    name = "length"

    @classmethod
    async def compute_score(cls, answer: str = "", target: int = 100, **kwargs):
        return SubScore(name=cls.name, value=1.0 if len(answer) >= target else 0.0)

result = await LengthGrader.grade(weight=1.0, answer=answer, target=200)
```

Use `info` for grader-specific details and `children` for nested results such as rubric
verdicts. `grade` applies the caller's weight and optional name override, then records the call
parameters under `_parameters`. `compute_score` may also return a bare float or a `(float, info)`
pair, which `grade` wraps in a `SubScore`.

## `SubScore`

A `SubScore` is one node in the grade breakdown tree. A leaf is a single measurement; a parent
preserves the measurements used to derive its value in `children`:

| Field | Default | Description |
|-------|---------|-------------|
| `name` | - | Name of this component (for a rubric verdict: the requirement checked). |
| `value` | - | Measurement, 0-1. |
| `weight` | `1.0` | Weight in the parent's combination; negative = penalty. |
| `children` | `None` | Input subscores this node was combined from. |
| `info` | `None` | Grader-specific details recorded on the evaluation span. |

`combine` returns a [`Grade`](/v6/reference/types#grade) carrying the subscores; a task can also
build one itself, as `Grade(reward=..., subscores=[...])`. A grade's subscores explain its reward:
the sum of each subscore's `value` times its `weight` equals `reward`.

Graders run as the second yield of a [task](/v6/reference/tasks). An
authoritative grader that needs a distinct environment can run as a
[`Task.verifier`](/v6/experimental/verifier-environments). For choosing a reward
that separates good work from bad, see [designing tasks](/v6/reference/advice).
