The serializable shapes agents, tasks, and graders exchange.

```python
from hud import Grade, Job, Run, Trace
from hud.types import Step
from hud.agents.types import AgentStep, Citation, SubagentStep, ToolStep
from hud.environment import Answer
```

## `Run`

The live handle for one task while its agent runs - what an agent's `__call__` receives. It is not a
result: the outcome is the graded [`Trace`](#trace) the rollout returns. Construct one over a connected
client for manual driving; after the block, `run.trace` holds the graded trace.

| Member | Type | Description |
|--------|------|-------------|
| `run.prompt` | `str \| list \| None` | The task's opening prompt as `tasks.start` returned it (text, or chat-style message list). |
| `run.prompt_messages` | `list[PromptMessage]` | The prompt as normalized user/assistant turns - what agents consume. |
| `run.prompt_text` | `str` | The prompt flattened to plain text, for string-only backends. |
| `run.trace` | `Trace` | The trajectory the agent fills. **The answer is `run.trace.content`.** |

## `Grade`

A task's verdict on one evaluation. A task yields one as its grade (`combine` builds it from
subscores), and the trace records the one the environment sent (`trace.grade`). Its serialized form,
`grade.model_dump(mode="json")`, is the grade frame that travels on the wire
(`{"score": ..., "done": ..., "isError": ..., "subscores": ..., ...}`), and
`Grade.model_validate(frame)` reads one back. Python code uses the field names; the frame uses
`score` and `isError`. Any other keyword, such as the fields a
[verifier](/v6/experimental/verifier-environments) reads, travels at the top level of the frame
(`Grade(reward=1.0, answer=...)`), and the platform records it with the grade; read them back from
`grade.model_extra`.

| Field | Type | Description |
|-------|------|-------------|
| `reward` | `float` | The reward; the frame's `score`. |
| `done` | `bool` | Whether the task is complete. |
| `content` | `str \| None` | Human-readable grade content. |
| `info` | `dict` | Extra metadata. |
| `is_error` | `bool` | Whether grading failed or never happened. |
| `subscores` | `list[SubScore] \| None` | The breakdown, as `combine` builds it; see [Graders](/v6/reference/graders#subscore). |

A grade with `subscores` must explain its reward: `sum(value * weight)` over the subscores equals
`reward` within 0.01, or validation fails. A grade frame whose `score` is a boolean, or whose
`done`, `isError`, `content`, `info` or `subscores` has the wrong type, is a protocol error.

`grade.to_summary()` is the frame without `info` at any level, the form the platform records and
safe to persist.

## `Job`

The receipt for one execution: the graded [traces](#trace) of a batch under one platform job id. Every
trace reports under a job, so even a single `task.run` returns a job of one. You get one back from
[`task.run` / `taskset.run`](/v6/reference/tasks#running).

| Member | Type | Description |
|--------|------|-------------|
| `id` | `str` | Platform job id. |
| `name` | `str` | Display name. |
| `traces` | `list[Trace]` | The graded traces, in expansion order (task-major, then group). |
| `group` | `int` | Rollouts per task. |
| `taskset_id` | `str \| None` | Platform taskset id when the job runs a synced taskset (`Taskset.from_api`), else `None`. |
| `reward` | `float` | Property: mean reward across graded traces, excluding `errors`; raises `ValueError` when no trace is graded. |
| `errors` | `list[Trace]` | Property: traces whose `grade.is_error` is true. |
| `results` | `dict[str, list[Trace]]` | Property: traces grouped by task slug - the alignment-safe alternative to `zip(tasks, job.traces)`, list-valued since `group > 1` gives several traces per task. |

```python
job = await ts.run(agent, runtime=LocalRuntime("env.py"), group=4)
print(job.reward)       # mean across graded traces
print(len(job.errors))  # traces without a grade
```

Each `run` call makes its own job by default. To report several calls under one job, pass the same
`Job(name=..., group=1, taskset_id=None)` as `job=` to each; each run registers it. Pass `id=` to
report under a job id you already hold, such as one shared by separate processes.

## `Trace`

The record of one graded evaluation - an ordered collection of `Step`s plus the outcome, and the unit of
training data. `rollout` returns one and a [`Job`](#job) collects them; every recorded step also
streams to the platform as one schema-tagged span.

| Member | Type | Description |
|--------|------|-------------|
| `steps` | `list[Step]` | The ordered trajectory. |
| `status` | `"completed" \| "error" \| "cancelled" \| None` | How the rollout ended (`trace.is_error` reads it). |
| `stop_reason` | `"done" \| "max_steps" \| "length" \| "timeout" \| "malformed_tool_call" \| None` | Why the rollout stopped: anything but `"done"` means a limit cut it off. |
| `content` | `str \| None` | The final answer (graded). |
| `grade` | `Grade` | The environment's verdict; an error ("not graded") until graded. |
| `reward` | `float` | Property: the graded reward (`grade.reward`). |
| `prompt_text` | `str \| None` | Property: the prompt the agent was given; `None` when no task started. |
| `trace_id` | `str \| None` | Keys the trajectory for training. |
| `slug` | `str \| None` | The task slug it came from; how [`Job.results`](#job) keys traces back to their task without positional zip. |
| `job_id` / `group_id` | `str \| None` | Batch and GRPO group. |
| `runtime` | `str \| None` | Where it ran: the control-channel url, or `hud://trace/<id>` when hosted. |

A rollout that fails before its session is live returns `Trace.failed(...)` (no prompt, no runtime); a
mid-run failure keeps the real trace - prompt, runtime, partial steps - marked as errored.

`hud.types.Step` is the shared skeleton (source, timing, error, plus the harness payloads: prompt
`messages` and `task_call` lifecycle RPCs). The tool-agent family subclasses it in `hud.agents.types`,
flat on the skeleton:

- **`AgentStep`** - the model's turn: `content`, `reasoning`, `tool_calls`, `done`, plus `model`,
  `usage`, and token-level `sample` when the backend is trainable.
- **`ToolStep`** - one tool round-trip: the `ToolCall` paired with its `ToolResult`.
- **`SubagentStep`** - a nested rollout's `Trace`, embedded whole.

Derived reads go through the trace's two query shapes - `trace.final(get)` (newest non-`None` answer
wins; `trace.error` is a view on it) and `trace.collect(get)` (every answer, in step order). Family
vocabulary stays at the call site:

```python
samples = trace.collect(lambda s: s.sample if isinstance(s, AgentStep) else None)
citations = trace.final(lambda s: s.citations if isinstance(s, AgentStep) else None)
```

## Answer & result types

### `Answer[T]`

When a task declares `returns=T`, the answer arrives wrapped
(`from hud.environment import Answer`): `content` is the answer parsed into `T` (or the original string
when parsing failed - grade it accordingly), `raw` is always the string as submitted.

```python
@env.template(returns=int)
async def count(word: str = "strawberry"):
    answer = yield f"How many letters in '{word}'?"
    yield 1.0 if answer.content == len(word) else 0.0
```

### `Citation`

A normalized citation across providers (`hud.agents.types.Citation`): `type`, `text`, `source`,
`title`, `start_index`, `end_index`. A reply annotation, not a grading input - an agent attaches
them to `AgentStep.citations`, and chat surfaces read the final reply's via the `trace.final(...)`
query above. A task that wants to grade sources should declare them in its `returns=` schema so the
agent submits them as part of the answer.

### Grading shapes

`SubScore` lives with the graders - see [Graders](/v6/reference/graders#subscore).

## Typed task I/O

Declare `input=` / `returns=` on `@env.template` to surface JSON schemas in the manifest and parse the
agent's answer into a typed `Answer[T]`. Any Pydantic model or standard type works.

These shapes flow through a [task](/v6/reference/tasks) run; the scores they carry come from the
[graders](/v6/reference/graders).
